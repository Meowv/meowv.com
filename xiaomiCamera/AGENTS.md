# XiaomiCamera 协作指南

适用于 `xiaomiCamera/` 及其子目录。继承仓库根目录 `AGENTS.md` 的通用规则；项目用途、启动、配置、接口和发布方式见 [`README.md`](README.md)。

## 修改边界

- 只修改本项目及用户明确授权的集成文件。Studio 的页面与调用逻辑位于 `studio/`，跨项目改动须分别遵守对应目录的约定。
- 按现有分层放置代码：`Core` 存契约，`Cloud` 处理小米云，`Protocol` 处理 CS2/MISS，主项目处理 HTTP、配置、会话与媒体输出。避免让协议层依赖 Web 或 UI 类型。
- 保留已有配置文件、SQLite 数据库及用户生成的媒体文件；不要将 `data/`、`bin/`、`obj/`、`build/` 及发布缓存纳入代码改动或提交。
- 不因文档或局部修复顺带升级 FFmpeg、.NET 依赖、媒体档位或协议参数。

## 实现约束

- 初始化接口与应用接口的凭据各司其职；HLS 清单、分片及状态使用短期播放票据。改动鉴权或票据生命周期时，检查授权码轮换、过期、设备绑定和响应状态的一致性。
- 云会话与数据密钥不得写入日志、API 错误、测试样本或媒体 URL。保留现有会话加密、密钥清零和旧数据库密钥迁移保护；不要在示例配置中放入真实凭据。
- 每台设备共享上游 CS2 会话与 FFmpeg 进程，播放票据可独立创建。修改媒体管线时检查包顺序、时间戳、队列上限、音视频同步、失败终止与空闲清理，避免静默丢弃压缩帧后继续输出损坏画面。
- 云台控制依附已就绪的播放会话，只向当前允许的型号发送单步指令。`sent` 仅表示发送成功；不得把它写成机身到位确认，也不要用有缓冲的 HLS 画面直接判断控制耗时。
- FFmpeg 解析顺序、`libx264` 预检、发布目录与校验缓存相互关联；修改其中一处时同步检查调用方、脚本和 README。发布脚本的网络下载与产物生成不属于日常静态验证。

## 验证

- 文档改动：核对路径、命令与实际源码或脚本，并运行 `git diff --check`。
- C# 改动：优先做相关文件的静态检查或定向验证。完整编译、完整构建和全量测试遵循仓库根目录的确认要求；不要将静态检查描述成运行时验证。
- Shell 脚本改动：至少运行 `bash -n <脚本>`，并在非 `C` locale 下检查帮助或 dry-run 路径；不为验证而直接执行发布或下载。
- 播放、声音、云台或 Studio 交互改动：条件允许时做目标环境的短时实际检查，分别记录服务端状态、媒体输出与浏览器可见结果。没有设备实测时明确保留该验证边界。
