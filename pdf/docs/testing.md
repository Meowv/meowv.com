# 测试说明

## 原则

测试需要证明工具生成了真实文件，并覆盖隐私、错误和资源释放边界。页面出现成功提示不等于处理正确，必须重新解析输出或检查下载内容。

本文描述测试入口和验收范围，不表示这些检查在当前环境已经通过。结果以本次命令输出和 CI 记录为准。

## 命令

```bash
# 单次运行 Vitest
pnpm test

# 监听模式
pnpm test:watch

# 类型检查
pnpm typecheck

# ESLint、Stylelint、Prettier
pnpm lint

# Playwright
pnpm test:e2e

# 静态生成
pnpm build
```

首次运行 Playwright 前，根据本机环境安装浏览器：

```bash
pnpm exec playwright install chromium
```

不要在未确认环境影响时使用系统级或全局安装。

## 单元测试

优先测试与 DOM 无关的纯函数：

- 页码范围与自定义分组解析；
- 每 N 页分组、奇偶页选择；
- 文件名清理和输出名称生成；
- 文件大小、耗时和页码格式化；
- 页面排序、删除、复制和旋转状态；
- 工具配置完整性与 slug 唯一性；
- 底层错误到 `PdfErrorCode` 的映射；
- 水印位置和平铺计算；
- 页码位置、格式和页面范围计算。

边界用例至少包含空输入、零、负数、倒序、重复页码、超过总页数、中文文件名、不可见字符、重复扩展名和 180/270/360 度旋转。

## PDF 集成测试

测试夹具必须是无敏感信息的最小文件：

```text
单页 PDF
多页 PDF
横向页面 PDF
混合页面尺寸 PDF
中文内容 PDF
带图片 PDF
损坏 PDF
加密 PDF
空白页面 PDF
JPEG / PNG / WebP
```

集成测试不要只比较文件大小。建议使用 `pdf-lib` 或 PDF.js 重新打开输出并验证：

- 合并页数、文件顺序和页面顺序；
- 各拆分分组的文件数与页数；
- 删除后至少保留一页；
- 提取与整理后的页面顺序；
- 页面旋转属性；
- 图片转 PDF 的页数和页面尺寸；
- PDF 转图片的文件数、格式和补零名称；
- 水印或页码对象确实写入；
- 基础元数据字段的修改结果；
- 多文件输出 ZIP 可读取且文件名无冲突；
- 加密、损坏和取消任务映射为正确错误。

## E2E

至少保留两个核心闭环：

### 合并

1. 从首页进入合并工具；
2. 添加两个有效 PDF；
3. 调整顺序；
4. 开始合并；
5. 捕获下载；
6. 重新解析下载内容，确认页数与顺序。

### 提取

1. 添加多页 PDF；
2. 选择指定页面；
3. 提取为一个 PDF 或多个文件；
4. 捕获 PDF/ZIP 下载；
5. 验证输出页数与顺序。

还需要覆盖：

- 文件选择和拖拽上传；
- 无效扩展名、MIME、文件头、损坏 PDF 和加密 PDF；
- 处理取消与失败后的重试；
- 刷新页面清空文件工作区；
- 深色模式持久化但不持久化文件；
- 键盘进入上传区、排序、对话框焦点与 `aria-live`；
- 200% 浏览器缩放；
- 移动端参数抽屉和固定操作栏；
- 捐赠页二维码为本站静态资源，且不影响工具入口。

## 隐私回归

用浏览器开发者工具执行一次真实处理，并检查：

1. Network 中没有包含 PDF、图片字节、文件名或 Base64 文件内容的请求；
2. `localStorage`、Cookie 和 IndexedDB 中没有文件、缩略图、水印历史或结果 Blob；
3. Console 与错误上报中没有二进制、文件内容或完整文件名；
4. 页面刷新后文件列表为空；
5. 处理完成或取消后 Object URL 被撤销；
6. PDF 内嵌 JavaScript、外部链接和附件没有自动执行或打开。

如果监控内存，连续重复大文件流程并等待垃圾回收后观察趋势。瞬时峰值不等于泄漏；重点是 PDF.js 文档、Worker、Canvas 和 Blob 是否持续累积。

## 性能与兼容性

建议至少检查：

| 场景        | 观察点                          |
| ----------- | ------------------------------- |
| 超过 100 MB | 有警告，可取消，失败信息明确    |
| 超过 500 页 | 缩略图分批加载，不无边界并发    |
| 3× 图片导出 | 内存警告、Canvas 上限与逐页释放 |
| 移动设备    | 不横向溢出，复杂任务提示桌面端  |
| Safari      | Worker、Blob 下载、WebP 回退    |
| Firefox     | PDF.js Worker、拖拽和下载       |
| Chrome/Edge | Clipboard、拖拽、键盘和下载     |

浏览器能力必须特性检测。没有 File System Access API 时使用普通下载；没有 OffscreenCanvas 时分批使用主线程 Canvas；没有 Clipboard API 或 Web Share API 时隐藏对应入口或使用下载回退。

## CI 范围

CI 在 Node.js 24、pnpm 11 下执行：

```text
pnpm typecheck
pnpm lint
pnpm test
pnpm build
```

成功构建后上传 `.output/public/`。默认 CI 不运行 Playwright，以避免把浏览器安装和跨浏览器差异混入快速质量门；发布前仍需单独运行 E2E 和人工隐私检查。

## 记录结果

交付说明应明确记录：

- 实际执行的命令；
- 每条命令的退出状态；
- 测试数量与失败数量；
- E2E 使用的浏览器；
- 未执行项目及原因；
- 仍未覆盖的浏览器、性能或隐私风险。

不得把静态检查、单元测试或构建成功描述为已经完成生产视觉、真实设备或大文件验证。
