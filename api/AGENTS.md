# API 协作指南

适用于 `api/` 及子目录。继承[根协作指南](../AGENTS.md)，用途、命令和模块约定见 [README](README.md)。

- 解决方案固定为 `Meowv.Api` 和 `Meowv.Api.Core` 两个项目。前者是唯一 HTTP 宿主，所有业务模块放在其 `Modules/` 下，按目录细分职责，不新增模块类库；后者只保存公共契约。
- 使用显式、泛型的 DI 注册；模块入口保持无业务状态，不在构造函数中注入 scoped 业务服务或模块清单。
- 宿主统一附加模块路由归属元数据；接口目录从实际注册端点读取，不维护独立路由清单。模块自行校验的访问凭据必须用 `EndpointAccessMetadata` 标明。
- 模块自行登记配置、依赖与 JSON 源生成上下文。保持裁剪分析与反射式 JSON 禁用，不为方便改成反射扫描。
- 新路由使用 `/api/<module>/...`。公共健康接口只表示宿主存活，模块就绪单独表达；可选模块故障不得阻止其他模块提供服务。
- 中间件顺序为可信代理转发处理、路由、CORS、限流、模块不可用拦截、认证、授权、端点。只信任本机回环代理的一跳转发头；认证必须在请求体和业务依赖绑定前执行；模块初始化、重绑统一使用公共管理策略与密钥，不单独实现模块管理认证。
- 公共配置和 SQLite 由宿主管理，根目录直接使用 appsettings.json / api.db；appsettings.Development.json 仅 Development 加载，不提交、不发布，生产密钥通过环境变量提供。模块只读取自己的配置与表，不改写其他模块数据。
- 新版按全新安装初始化，不保留旧版数据导入工具或兼容读取逻辑；现有个人数据不自动删除、不发布。所有相对文件路径以内容根目录解析，不依赖工作目录。
- API 的运行、发布和工具准备不得依赖旧 `xiaomiCamera/`。仓库不再包含旧项目源码；根构建脚本对既有旧部署产物的保留逻辑仅用于人工回滚。
- 摄像头媒体流按设备共享，并发容量包含回收中的流；云会话变更撤销旧播放票据并停止旧媒体流，公共授权码轮换也必须使旧票据失效。
- 初始化页面统一为 `/setup`，模块只提供受公共管理策略保护的初始化 API，不增加独立初始化页面或旧初始化路由兼容。
- C# 改动优先相关静态检查与定向验证；完整构建、全量测试和部署遵循根目录确认要求。Shell 至少执行 `bash -n` 和非 `C` locale 的帮助或 dry-run；不要为检查而下载工具。
